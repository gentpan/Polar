# 友链订阅

入口：`/subscriptions/`，页面模板 `pages/subscriptions.php`。首次启用自动创建；已有同模板页面或同路径页面会保留。自定义导航需要在 WordPress「外观 → 菜单」添加该页面；主题默认导航直接显示「订阅」。两种菜单都支持角标。

## 使用

1. 后台「链接」编辑友情链接，在原生「高级 → RSS 地址」填写 RSS / Atom 地址，并保持链接公开可见。
2. 「外观 → Polar 设置 → 友链订阅」选择每 4 小时（默认）或 6 小时同步，保存设置。
3. 点击「立即同步订阅」可以马上抓取，界面显示处理进度、新收录文章数和失败源数。
4. 订阅页按原文发布时间倒序，支持全部／今日、按朋友筛选，每次显示 30 条，继续阅读不会跳转页面。

## 计数与数据

- 菜单角标表示已同步到本地、在站点时区今日零点以后发布的文章数，不是未读数，也不是本轮首次发现数。大于 99 显示 99+，无更新时隐藏。
- 时区采用 WordPress「设置 → 常规」；日期在服务端计算，前端每分钟、站内切换、重新激活标签页和跨零点时校准。阅读页面不会清空角标。
- Atom 使用 published，RSS 使用 pubDate / Dublin Core date。仅有 updated 的文章标记为「发布时间未提供」，不算今日更新。未来日期暂不展示。
- GUID 与文章链接去重；同一文章再次同步只更新标题、摘要等，不重复新增。已知的原始发布时间保留。跨源相同文章链接只展示、计数一次。
- 原文地址、标题、纯文本短摘要、发布时间写入非自动加载的 WordPress option：`feng_feed_source_{link_id}`；每个来源保留最近 200 条记录，不混入博客文章，也不下载全文、图片或附件。
- 首次只能获取源站 RSS 当前提供的文章。旧记录在后续抓取时合并保留；超过每源 200 条时淘汰最旧记录。
- 抓取失败保留上次成功结果，错误信息仅在后台显示。修改 RSS 地址会清理旧源缓存；只修改名称或介绍保留缓存。删除、隐藏友链后即从订阅列表排除。

## 定时和安全

使用原生 WP-Cron；每个 worker 处理一个订阅源，剩余源通过后续单次任务执行，数据库锁避免手动与定时同步重叠。单源请求总预算约 12 秒，响应最大 1 MiB，最多 3 次跳转，每跳重新验证公开 HTTP(S) 地址；拒绝本机、私网、凭据 URL、外部 XML 实体。输出经过纯文本清理和 HTML 转义。

WP-Cron 依赖访问触发，低流量站点不保证准点。需要固定时刻执行时，应在服务器配置定时调用 `wp-cron.php` 或 WP-CLI cron，而不是让访客页面等待网络请求。参考 [WordPress WP-Cron 文档](https://developer.wordpress.org/plugins/cron/)。

手动同步只允许 `manage_options` 用户，以 POST + nonce 校验；一分钟内限制重复发起。访客接口只读取本地缓存。

## 文件

- `inc/inc-feed.php`：解析、缓存、去重、定时、计数、页面创建。
- `inc/inc-feed-ui.php`：页面渲染、公开缓存接口、后台设置和受保护的同步入口。
- `assets/js/feed.js`、`assets/css/feed.css`：筛选、加载更多、主题色角标及柔和动画。
- `assets/js/feed-admin.js`：后台手动同步进度。

动画参考用户提供的 Notification badge，菜单本身不位移，角标独立滑入、缩放、淡入和消除模糊；遵循减少动态效果偏好。
