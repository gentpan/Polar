# Polar · 开发中

独立编写的 WordPress 主题：FAFAFA 页面底色、纯白内容卡片、居中布局、少量点缀色、深色模式、连续圆角和无刷新交互。参考其他网站的设计语言，但没有使用其私有 HTML 类名、CSS 变量、媒体结构或 JS/CSS 文件，不依赖父主题。

当前不提供压缩包。此前的开发安装包已按要求删除，待用户确认开发完成后再打包。

## 目录结构

采用 WordPress 经典 PHP 主题的模板层级。根目录保留 WordPress 识别的入口文件；使用文档集中在 `docs/`；AI 目录职责见 `ai/README.md`，开发助手规则见根目录 `AGENTS.md`。

```text
polar/
├── AGENTS.md               编程助手维护规则
├── docs/                   功能与使用说明
├── ai/                     AI 角色与提示词组织说明
├── assets/                 CSS、JavaScript 和主题自带图片
│   ├── css/
│   ├── js/
│   └── images/
├── inc/                    功能模块，统一以 inc- 命名
│   ├── inc-setup.php       主题能力、菜单、编辑器支持
│   ├── inc-settings.php    后台设置与基础页面创建
│   ├── inc-assets.php      样式、脚本、字体加载
│   ├── inc-customizer.php  自定义器
│   ├── inc-page.php        页面辅助、分页、模板路径迁移
│   ├── inc-comment.php     评论输出、Emoji、提交处理
│   ├── inc-article.php     文章统计
│   ├── inc-media.php       媒体辅助
│   └── inc-icons.php       SVG 与社交链接
├── pages/                  后台可以选择的自定义页面模板
│   ├── archives.php
│   ├── friends.php
│   ├── about.php
│   └── guestbook.php
├── template-parts/         可复用显示片段，保持单层
├── functions.php           仅作为功能模块加载入口
├── style.css               WordPress 主题信息
├── theme.json              编辑器全局配置
├── index.php               首页文章列表与最终回退模板
├── single.php              文章
├── page.php                普通页面
├── archive.php             分类、标签、作者、日期归档
├── search.php              搜索结果
├── searchform.php          搜索表单
├── comments.php            评论区模板
├── header.php / footer.php 公共页头与页脚
├── 404.php                 未找到页面
└── screenshot.png          后台主题预览
```

`pages/archives.php` 是可选的文章存档页面，根目录 `archive.php` 是 WordPress 原生归档入口，两者用途不同。页面模板声明保留 `Template Name`，后台创建页面和默认导航均使用新路径。升级时会一次性将旧 `page-templates/` 分配迁移到 `pages/`，不改变页面正文、地址或 ID。

文章上传附件仍由 WordPress 媒体库管理，保存在站点 `wp-content/uploads/` 中；只有主题自带图片放进 `assets/images/`。开发测试、参考资料及本地运行文件位于主题之外。

目录参考：[WordPress 经典主题文件组织](https://developer.wordpress.org/themes/classic-themes/basics/organizing-theme-files/)。

## 安装（完成开发后）

1. 在「外观 → 主题 → 安装主题 → 上传主题」上传最终确认的主题安装包，预览后启用。
2. 打开「外观 → Polar 设置」，点击页面底部的「创建基础页面」。它会创建已发布的存档、友情链接、关于、留言页；已有同模板页面不会重复创建或覆盖正文。
3. 在「页面」里编辑正文。也可新建页面，在模板选项中选择 `Polar · 文章存档`、`Polar · 友情链接`、`Polar · 关于`、`Polar · 留言`。
4. 在「外观 → 菜单」分配主导航和页脚导航；未分配主导航时自动显示首页及已发布的四种模板页面。
5. 在「设置 → 阅读」选择最新文章或静态首页。最新文章模式显示首页介绍、文章卡片和分类专题。普通静态首页使用页面模板。

运行要求：WordPress 6.6+、PHP 7.4+。无需构建工具或付费插件。文章内页大标题使用用户指定的「快看世界体」CDN 字体，加载失败时回退系统字体。当前集成验证环境为 WordPress 7.1 / PHP 8.5 / MySQL 8.4。

## 后台设置

「外观 → Polar 设置」提供原生标签页配置：

- **外观与交互**：浅色/深色/跟随系统。内容宽度与点缀色使用主题固定设计值，不提供全站背景图片、视频设置；无刷新导航和滚动入场固定开启。
- **首页与内容**：欢迎语、标题、简介、文章数量、评论框提示和 AJAX 提交开关。
- **关于与社交**：个人资料、头像与社交链接。
- **页脚与友链**：页脚短句、版权、建站日期、备案、友链介绍和申请说明。
- **AI 助手**：文字与图像服务、模型、Endpoint、密钥与连接测试。
- **养成宠物**：四种外观、成长互动、显示位置与 AI 额度。
- **友链订阅**：RSS 同步周期、手动同步及状态。

保存使用 WordPress Settings API，并检查管理员权限、nonce 和字段格式。系统减少动态效果偏好仍受尊重，复杂插件页面与自定义器预览保留原生导航兼容处理。

「外观 → 自定义 → Polar · 快速外观」可预览首页文案，使用同一组设置。站名、简介、Logo 使用 WordPress 站点身份设置。

## 评论管理

- 在「设置 → 讨论」控制登录限制、昵称/邮箱必填、人工审核与线程深度；主题统一显示全部可见评论，忽略评论分页设置。
- 在文章或页面的「讨论」选项中开启/关闭评论，在「评论」中审核、回复、编辑或移入垃圾箱。
- AJAX 提交继续调用 WordPress 核心评论处理，保留登录/密码/关闭状态、重复评论及频率限制、过滤和审核钩子。
- 提交成功后显示对号 Toast，无刷新定位对应评论；待审核内容按 WordPress 的提交者身份或审核链接显示，不向普通访客公开。错误时保留输入，不自动重试造成重复留言。
- 关闭 AJAX 或禁用 JavaScript 后，表单继续通过 WordPress 原生地址提交。

## 交互与扩展

导航在顶部透明，滚动超过 72px 后收为磨砂胶囊，回到 24px 内恢复。页脚直接显示在背景上，没有额外面板。卡片在进入视口时淡入并轻移，离开后不反复隐藏；系统减少动效偏好下直接显示。

文章卡片和友链头像使用惰性图片模板，进入视口才挂载图片；无 JS 时保留 noscript 图片。正文与链接始终由服务器输出，便于搜索、辅助技术和原生浏览。背景图与正文图片没有模糊滤镜，磨砂仅作用于面板表面。

`#xf-view` 为页面交换区，包含页头、正文和页脚；全局背景、搜索框、图片预览和加载条在交换区外。导航同步标题、元信息、历史记录、滚动位置与正文焦点。主题保留自己的 `xf-*` 组件命名空间，PHP 使用 `feng_*` 前缀。

扩展组件可监听 `xf:mounted` / `xf:before-unmount`，通过 `event.detail.view` 初始化或清理。链接/页面标记 `data-xf-native` 可强制使用原生导航。

同运行依赖的页面使用 PJAX；不同脚本依赖、WordPress Interactivity API、iframe、复杂插件表单、后台/登录/下载和加载失败会回退原生导航。没有执行未知插件脚本来强行维持无刷新。具体插件组合需要在部署站验证。

## 评论视觉与 Emoji

评论框移至列表上方，采用浅灰圆角编辑区、原生 Emoji 工具栏、胶囊资料输入框和圆形发送按钮；评论使用圆角卡片，回复显示父评论作者。Emoji 默认灰色半透明，悬停、键盘聚焦或按下时恢复彩色并放大；点击按光标位置插入，多余表情可展开，手机自然换行。使用 WordPress 官方排除标记避免工具栏 Emoji 被替换为远程图片。保留审核、回复、无 JS 原生提交和 PJAX；评论不分页。

开发约定：不自动打包。评论区不显示保存勾选项和附加说明，提交后默认通过 WordPress 评论 Cookie 记住昵称、邮箱、网站；不会保存评论正文。Emoji 按容器宽度铺满首行，加号固定在右端，点击一次向上浮出额外两行，不改变下方表单位置；再次点击 × 或按 Escape 收起。

文章内页标题字体来源：https://static.bluecdn.com/fonts/kuaikanshijieti.css 。仅在文章详情加载，并作用于文章大标题；首页卡片、普通页面与正文维持原字体，无刷新进入文章时同样生效。

Logo 文字和顶部菜单试用用户指定的阿里妈妈方圆体：https://static.bluecdn.com/fonts/alimama-fangyuanti.css 。字体样式集中在 `assets/css/typography.css`；可将 `--feng-menu-font` 改回 `var(--xf-font)` 单独恢复菜单原字体，Logo 不受影响。

页面切换时，背景图片和视频保留在公共文档层；相同的样式表节点保持原位，只插入新增样式并移除不再需要的样式，避免重新插入公共样式表导致背景缩放动画重启。暂停状态和动画进度在 PJAX 页面之间连续保留。

### 站点控制面板

`inc/inc-dashboard.php` 负责公开数据查询与 AJAX，`template-parts/dashboard.php` 负责内容，`assets/css/dashboard.css` 和 `assets/js/dashboard.js` 负责外观与交互。面板仅在打开时读取数据，日期链接进入 WordPress 原生日期归档；隐藏私密、草稿及密码保护文章的内容与评论。置顶在文章编辑器设置，热门标签来自已使用的文章标签，没有数据时显示空状态。统计包含公开文章数、已审核留言数、从第一篇公开文章至今的记录天数。按 Esc 或关闭按钮恢复原页面位置，站点导航继续使用 PJAX。

文章未设置特色图片时，默认使用 `https://img.et/1920/1080?type=landscape&s=文章ID`。列表、专题和文章封面共享同一地址，已有特色图片优先；默认图不导入媒体库，卡片继续延迟加载。

文章分享按钮展开微信、微博和 X 的圆弧菜单；微信复制文章链接，微博和 X 打开编辑页供访客自行发布。相邻文章箭头保持圆形，仅悬浮放大图标；分享菜单支持 Esc、点击外部收起及减少动画偏好。

评论 AJAX 提交成功会显示约半秒的对号描边、旋转、模糊淡入和上浮动画，反馈停留约 3.6 秒。待审核留言使用“已提交，审核通过后公开”的提示；失败不显示成功对号。提示独立于 PJAX 内容，减少动态效果时显示静态对号。

存档年份使用 WordPress 重写规则：`/archives/2025/` 显示指定年份，`/archives/all/` 显示全部，`/archives/` 默认当前年份。路径跟随存档页面的实际别名及父页面；旧的 `?feng_year=` 链接以 301 跳转到新路径。路由配置发生变化时才刷新重写规则，年份切换保留 PJAX，规范链接也带对应的年份路径。

评论提示文字的显隐为 1.1 秒缓动：切换输入项时，空字段恢复提示，已有内容保持隐藏；表情按钮临时接管焦点时保持提示状态。输入框使用本机彩色 emoji 字体并放大至 145%，正文仍为 14px。页面进入为 850ms、滚动显现为 1000ms，减少动态效果设置继续生效。

### 整图文章卡片

分类列表与专题共用 `template-parts/post-card.php`，上方独立显示图片，仅底缘保留短渐变；下方文字区使用图片主色生成的深色纯色背景，标题与摘要为浅色。取色结果缓存 12 小时并在服务端输出，首次取色随图片可见后按需执行，前端最多并发两次；轮播加载的卡片沿用同一模板与取色机制。首页最近更新的紧凑横条保持白色。

### 当前浅色外观

全站背景图片与视频设置已移除，不输出壁纸元素及暂停按钮。浅色页面底色为 `#FAFAFA`，Hero、文章、评论、专题和控制面板卡片使用纯白表面；输入控件保留浅灰色以区分操作区域。导航与页脚采用深色文字，深色模式仍可切换。历史背景素材文件保留，但不在前台使用。

文章 Banner 底边使用独立的 `feng-entry-curve` 内联 SVG 连续贝塞尔曲线，填充跟随正文纸面色，取代横向 48% / 纵向 3% 的扁椭圆圆角；底部重叠 1px 防止接缝。手机端降低曲线高度，首页 Hero 保持独立圆角结构。

首页专题最多展示六个非空分类，分类标题旁的“查看全部”使用原生分类链接并接入 PJAX。右侧箭头每次在本页滑动三篇，按发布日期和 ID 倒序，首尾禁用对应按钮。每组通过公开只读接口按需获取，浏览过的分组在当前页面缓存；切换约 1 秒，不产生横向滚动条，减少动态效果时直接切换。无 JavaScript 时仍可通过分类链接查看全部文章。

导航使用独立的 `assets/css/navigation.css` 与 `assets/js/navigation.js`：菜单项底部有点缀色细线及柔和光晕，下拉浮层采用圆角、细描边和圆润 SVG 指向尖角，约 650ms 浮现。保留原生 WordPress 菜单链接和层级；默认菜单会在“首页”下列出最多六个非空分类。支持悬浮、展开按钮、方向下键与 Esc、屏幕边缘定位及 PJAX 重建；超过四项自动双列，窄屏改为单列。

“最近更新”使用 `template-parts/activity.php` 与 `activity-item.php`：文章和说说按时间合并，一行一条，桌面缩略图 96×82px，每组默认三条。标题右侧前后切换，不显示分类筛选和底部分页；专题保持大图轮播。

## AI 助手与主题设置

入口为 **外观 → Polar 设置 → AI 助手**。后台使用 WordPress Settings API、原生标签页、表单、按钮与通知；原有外观、首页、社交和页脚配置保持独立。

- 文字与封面分别保存服务商、协议、Endpoint、模型 ID 和 API Key。地址支持基础地址或完整生成接口；自定义服务需要兼容所选协议，不接受任意不同的 API 格式。
- 文字支持 OpenAI Responses 与 Chat Completions；封面支持 OpenAI Images 与百炼同步图像生成。DeepSeek 预设只用于文字。
- 模型预设核对于 2026-09-06：DeepSeek V4 Flash / Pro；OpenAI GPT-6 Astra、GPT-5.6 Luna / Sol / Terra；千问 Qwen3.8 Flash / Max、Qwen3.7 Plus；图像包括 GPT Image 2、Qwen Image 3.0 Pro、Wan2.7 Image Pro。预设可编辑，实际可用性依账号、地域及服务商权限而定。
- 千问默认使用仍受支持的北京地域 DashScope 地址。可改为 `https://业务空间ID.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`；图像完整路径为 `/api/v1/services/aigc/multimodal-generation/generation`。其他地域需使用其对应地址和密钥。
- 保存后可测试。文字测试发送简短请求；封面测试真实生成一张图片并入库，会产生服务商用量。

在文章编辑页的 **Polar AI 助手** 中可一键生成摘要、提取关键词和生成横版封面。区块编辑器中位于底部原生「元框」区域（拖动或使用上下方向键展开）；传统编辑器中位于正文下方。使用当前编辑中的标题和正文，正文最多取前 18,000 字；封面使用其中前 5,000 字。文章内容仅在点击生成时发往所配置的服务。

摘要和关键词先预览、可编辑后应用。关键词添加为 WordPress 标签并保留已有标签。封面有自然摄影、极简设计、柔和水彩、电影质感、杂志插画五种预设，可附加画面要求；生成后保存至媒体库，由用户决定是否设置为特色图片。最后需保存草稿或更新文章，工具不会自动发布文章。

密钥存入不自动加载的独立 WordPress option，不进入 REST 配置、前台脚本或设置页 HTML；备份数据库时仍应按含凭证数据处理。留空保留已有密钥；切换服务、协议或地址会清除旧密钥，需重新填写。请求要求登录、有效 nonce 与文章编辑权限；配置测试仅管理员可用，图片还要求上传权限。仅允许可公开访问的 HTTPS 目标，禁止转发密钥到下载域名，限制响应/图片大小并验证图片类型。文本请求最长 60 秒，图像请求最长 150 秒，站点 Web 服务器的超时也需允许相应时长。若本地代理把域名解析为 `198.18.*` 等私有/保留地址，WordPress 安全 HTTP 校验会阻止请求，应调整代理 DNS 配置而非关闭主题安全校验。

官方参考：[DeepSeek API](https://api-docs.deepseek.com/)、[OpenAI 模型](https://developers.openai.com/api/docs/models)、[OpenAI 图像生成](https://developers.openai.com/api/docs/guides/image-generation)、[千问 OpenAI 兼容 API](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)、[百炼图像生成](https://www.alibabacloud.com/help/en/model-studio/text-to-image)。

验证：本地模拟 HTTP 响应覆盖两种文字协议、两种图片协议、鉴权与 nonce、密钥保存及错误脱敏、并发锁、图片验证；区块和传统编辑器均验证生成 → 预览 → 应用 → 草稿保存。未配置真实供应商密钥，未执行付费模型的联网生成。测试附件、草稿和临时密钥不随主题提供。

## 图标规范

主题界面统一使用 `inc/inc-icons.php` 中的内联 SVG 图标，不加载 Font Awesome 或图标字体。共同规范为 `24 × 24` 画布、`1.6` 描边、圆端点与圆连接、`currentColor` 单色；顶部工具栏统一显示为 `18 × 18px`，正文和元信息按所在控件缩放。控制面板使用统一描边的默认图标与关闭图标，点击打开或关闭时以 650ms 淡入、模糊和缩放切换，不变色、不倾斜；悬浮只放大。

搜索、深浅配色、关闭、播放/暂停、分页与外链箭头、评论及分享均调用 `feng_icon()`。前端动态插入的下拉箭头和评论成功对号由同一 PHP 图标表输出，避免维护第二套 SVG 路径。新增图标应继续添加至该文件；文章封面弧线、下拉气泡尖角属于布局图形，单独保留。评论 Emoji、文章内容和 WordPress 原生后台控件不属于主题功能图标。

## 养成宠物

**外观 → Polar 设置 → 养成宠物** 提供小鸟、猫咪、狐狸、兔子四种外观，支持改名、显示位置、手机开关、AI 开关与每日额度。采用全站共同成长档案，切换外观不清零；有效阅读、新审核评论、投喂和摸摸可积累经验。

默认小鸟位于左下角，AI 默认关闭。启用 AI 后复用「AI 助手」文字服务，按真实状态和近期日记回答；未配置或请求失败时使用本地问答。完整方案、计分规则、数据维护和验证范围见 [PET.md](docs/PET.md)。

## 前台说说

`pages/talks.php` 提供 `/talks/` 说说页：错落便签、点击放大、右上角关键词、搜索与筛选、图片和前台发布管理。访客只读，登录用户可以发布和管理自己的内容，管理员可管理全部。使用原生 `feng_talk` 内容类型与 `feng_talk_tag` 分类法，正文存于 `LONGTEXT`，沿用 `utf8mb4`，不增加独立数据库表或后台说说编辑菜单。详见 [TALKS.md](docs/TALKS.md)。

## 阅读增强

文章页已增加滚动目录、阅读进度、章节链接复制、专注阅读、打印、可折叠摘要卡与同分类推荐；区块编辑器增加原生提示卡和折叠问答样板。AI 摘要沿用作者生成、预览、应用、保存流程，前台区分手写与 AI 辅助摘要，访客打开页面不调用模型。详细入口与验证说明见 [READING.md](docs/READING.md)。

主导航的存档入口统一放在右侧日历按钮。骰子按钮先旋转约 650ms，再通过现有无刷新导航打开随机文章；从全部已发布、无密码文章中等概率抽取，多篇文章时避开当前文章。未启用 JavaScript 时保留服务器随机跳转；请求失败可再次点击，减少动态效果模式不旋转。
