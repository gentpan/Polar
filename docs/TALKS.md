# 前台说说

入口：`/talks/`。页面使用 `pages/talks.php`，默认导航增加「说说」。如已有自定义 WordPress 菜单，继续尊重该菜单，可自行添加此页面链接。

## 使用方式

- 未登录可以浏览、搜索、点击关键词筛选、展开完整内容和查看图片。
- 登录后点击底部加号发布。普通订阅者也可以发布；每个用户只能编辑、删除自己的说说，管理员可管理全部。
- 正文最多 4000 字，关键词最多 4 个、每个最多 20 字，地点为可选手动填写。
- 支持最多 4 张 JPEG、PNG、WebP 或 GIF 图片。单张上限取「5 MB」与服务器实际限制中的较小值，界面同步显示；长边最多 4096 像素，总上传大小也受服务器限制。
- 点击卡片放大查看；自己的卡片详情中有编辑和删除按钮。删除移入 WordPress 回收站，操作通知提供撤销。
- 底部的排列按钮可以在错落和整齐之间切换，此偏好只记在当前浏览器。
- 初始显示最新 18 条，点击「再翻一些」继续加载。搜索和关键词筛选查询全体已发布说说，不局限于已加载的卡片。
- 地址中的 `#talk-编号` 可直接打开一条说说，包括列表首屏之外的内容。

全部创作和日常管理在前台完成，没有单独增加 WordPress 后台「说说」编辑菜单。登录沿用 WordPress 登录状态，不另外保存密码，也不自动开放站点注册。

## 为什么这样存储

不另建一套独立数据库，也不用中文作为内部类型标识。采用 WordPress 自定义内容类型 **`feng_talk`**，界面名称显示为 **「说说」**。

| 内容 | WordPress 存储位置 |
| --- | --- |
| 正文、作者、时间、发布状态 | `{前缀}posts`，`post_type = feng_talk` |
| 正文文本字段 | `post_content`，原生 `LONGTEXT` |
| 中文、Emoji | 沿用数据库 `utf8mb4` 字符集；本地实际表已验证 |
| 关键词 | 独立分类法 `feng_talk_tag`，使用原生 terms、term_taxonomy、term_relationships 表 |
| 图片 | WordPress 附件记录与媒体文件；附件 ID 列表存入 `_feng_talk_images` 元数据 |
| 手动地点 | `_feng_talk_location` 元数据 |

说说与普通文章独立存储，首页「最近更新」会合并展示；文章分类专题、文章归档和文章搜索仍只查询文章。它仍可随 WordPress 内容和媒体一起备份、导出。关闭或更换主题不会删除已存的说说。

## 界面与实现

参考本地 Utterlog 的散落便签：白色纸片、小幅倾斜、不同高度、右上角彩色关键词。宽屏三列，中等宽度两列，手机单列；布局根据实际高度调整，避免长卡片互相盖住。详情从窗口中央轻微缩放展开约 280ms，收起约 180ms；列表卡片入场约 1 秒，遵循系统减少动态效果设置。

- `inc/inc-talk.php`：内容类型、存储、权限、查询、图片上传与前台接口。
- `pages/talks.php`：页面、工具条和编辑器。
- `assets/css/talk.css`：便签布局及动画。
- `assets/js/talk.js`：筛选、分页、编辑、图片预览和详情展开，接入现有 PJAX 生命周期。
- 功能图标继续使用 `inc/inc-icons.php` 的统一内联 SVG。

首次由管理员访问时，会在未存在同路径页面的情况下创建 `/talks/`，不替换已有页面内容。也可将现有页面指定为「Polar · 说说」模板，或使用主题的原生基础页面创建功能。

服务端检查登录、nonce 和内容归属，不能通过伪造文章 ID 修改普通文章或他人的说说。保存带内容版本校验，避免旧页面覆盖新修改；并发写入使用数据库锁，重复提交使用请求标识防止重复发布。每位用户每天最多创建 50 条。上传校验文件类型、大小和尺寸；SVG、可执行文件和任意附件 ID 不接受。

正文按纯文本存储与展示，保留换行，不执行 HTML。图片移除或说说删除不会立即擦除媒体文件，避免破坏引用；WordPress 回收站的保留期限仍受站点设置控制；站点关闭回收站时，前台会拒绝不可撤销的删除。近期成功请求的防重记录最多保留每位用户 12 项。

## 验证范围

本地验证了未登录拦截、普通登录用户发布、跨用户越权拦截、管理员管理、Unicode/Emoji/引号/换行保存、版本冲突、真实 HTTP 图片上传、无效图片拦截、重复提交防重、回收站和撤销、公开搜索与关键词筛选。

浏览器验证了前台发布 → 展开 → 编辑 → 删除 → 撤销流程，18 条到 21 条的加载无重复，以及桌面卡片、图片混排和手机布局。验证用账号、图片和便签均为临时测试数据，完成后清理，不作为用户的正式内容保留。
