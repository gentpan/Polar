# Polar 养成宠物

已实施方案：全站共同养一只宠物，后台可选择小鸟、猫咪、狐狸或兔子。四种外观共享成长档案；更换宠物、改名和暂时关闭功能都不会清空经验。

## 方案选择

| 方案 | 特点 | 结论 |
| --- | --- | --- |
| 每位访客各养一只 | 需要账号或依赖浏览器存储，清理缓存容易失去进度 | 不作为当前版本 |
| 全站共同养一只，规则负责成长，AI 负责对话 | 能与博客阅读、评论自然关联；数据真实，费用可控 | **当前实施** |
| AI 自主决定成长、主动生成每日故事 | 每次互动都可能产生费用，状态容易不一致，容易编造经历 | 不用于计分 |

参考了 Westlife 中的小鸟投喂、亲近程度和昼夜表现。Polar 使用独立实现，未改动 Westlife，也没有导入它的历史数据。插画为四张分层的本地 SVG。头部、身体、前爪／翅膀、耳朵、尾巴、嘴和眼睛分别设置关节，通过浏览器原生 Web Animations API 播放配合动作，不再让整个图片上下浮动。不需要外部动画框架。

## 后台使用

进入 **外观 → Polar 设置 → 养成宠物**：

- 启用或关闭宠物，选择外观和名字。
- 选择左下角或右下角，控制是否在手机上显示。
- 启用 AI 对话，并设置全站每天的 AI 请求上限，默认 10 次，允许 1–60 次。

默认启用小鸟「啾啾」，首页放在最新说说右侧，其余页面使用后台选择的边角位置；AI 对话默认关闭。猫咪叫「团团」、狐狸叫「栗子」、兔子叫「糯糯」，各有不同的食物和对话性格。

前台点击宠物打开小窝，可查看状态、投喂、摸摸、查看日记和提问。「本次先休息」只对当前标签页生效，保留一个唤醒入口。面板支持关闭按钮、点击外部和 Esc；移动端限制在视口内，内容可独立滚动。动画遵循系统的减少动态效果设置。

## 成长规则

| 行为 | 成长值 | 限制 |
| --- | ---: | --- |
| 有效阅读 | +1 | 前台可见累计 25 秒，并进入正文区域；同一访客同一篇每天一次，每人每天最多 5 篇，全站每天最多 100 次 |
| 新通过审核的评论 | +8 | 每条评论仅奖励一次，重新审核不重复奖励；每天前 50 条有经验，之后仍记录评论次数 |
| 投喂 | +3 | 每人每天最多 3 次，间隔 30 分钟；全站每天最多 30 次 |
| 摸摸 | +1 | 每人每天最多 5 次，间隔 1 分钟；全站每天最多 40 次 |
| AI 对话 | 0 | 不改变经验、饱食度和连续陪伴天数 |

评论只统计公开、无密码内容下通过审核的普通评论，包含回复；待审核、私密内容、Pingback 和 Trackback 不参与。功能启用前的已审核评论不批量补分。已经获得的成长奖励不会因评论随后删除而扣回。

成长阶段为：初遇 0、熟悉 40、亲近 140、默契 360、伙伴 800。等级和进度显示在面板中，亲近阶段起增加星光装饰。四种宠物使用同一套成长规则。

按 WordPress 的站点时区，23:00–07:00 显示睡眠状态。投喂后饱食度恢复到 85%，之后每小时下降约 3 点，最低保留 15%。离开不会死亡、丢失经验或消失；中断连续陪伴只影响连续天数。日记记录真实互动次数，空白日期显示零，不编造故事。

## AI 如何了解宠物

1. 在 **AI 助手** 中配置文字模型、Endpoint 和 API Key，使用已有连接测试。
2. 在 **养成宠物** 中打开 AI 对话。
3. 访客主动提问时，服务器发送宠物名字、性格、当前状态、累计统计、最近七个自然日的日记以及当前页面最近三轮对话。
4. AI 按这些资料回答，例如「你昨天吃了几次？」「最近有人来陪你吗？」「还差多少经验升级？」。

日记由服务器根据实际事件整理，不依赖 AI 定时生成。缺少历史记录时明确说明。无密钥、关闭 AI、请求失败、冷却或达到限额时，自动改用本地日常问答，仍能回答投喂、阅读、评论、睡眠和成长问题。

每位访客每天最多 3 次 AI 请求，间隔至少 30 秒；匿名访客另有同一网络每天 6 次的限制。全站额度在请求发出前占用，失败也计入，避免错误重试放大用量。这是请求次数上限，不是服务商金额预算。没有主动后台聊天或定时模型调用。

模型只负责生成回复，没有任何修改成长、执行操作或访问后台的工具。对话上下文视为访客提供的资料，当前服务器统计才是状态来源。AI 回复仍可能出错，面板显示的数值以服务器记录为准。

## 数据与维护

- `inc/inc-pet.php`：成长规则、日记、身份、计分事务、额度、AI 对话、AJAX 和清理任务。
- `inc/inc-pet-ui.php`：前台小窝、资源加载、后台预览。
- `assets/js/pet.js`：交互和服务端状态。
- `assets/js/pet-motion.js`：四种宠物的独立关节动作、播放打断和待机调度。
- `assets/css/pet.css`：小窝布局和 SVG 基础样式。
- `assets/images/pet-*.svg`：四种外观。
- `inc/inc-settings.php`：WordPress 原生主题设置字段。

没有增加主题目录层级，继续使用现有的四个顶层文件夹。

主题自动创建两张 InnoDB 表：`{WordPress 前缀}feng_pet_state` 保存共同档案，`{WordPress 前缀}feng_pet_events` 保存限额计数。服务端通过事务和单行锁处理并发计分。读取凭据绑定访客、文章和签发时间，至少经过 20 秒才可兑换；真实前台要求可见 25 秒。它用于合理计分与限流，不是无法绕过的机器人识别服务。

匿名访客使用签名的 HttpOnly Cookie 区分身份；网络限额只存每天变化的 HMAC，不存原始 IP。宠物事件不保存姓名、邮箱和评论正文。近期日记保留 30 条日期记录，AI 只获取最近七个自然日；限额事件通过 WordPress 每日任务清理，最多约 32 天。累计统计长期保留。

对话仅保留在当前页面内存，不写入本站数据库或浏览器持久存储；兼容的 PJAX 跳转保留对话，原生刷新后清除。主动使用 AI 时，问题和近期对话会发送给站长所配置的服务商，前台有说明；服务商自身的处理规则由该服务商决定。API Key 继续留在服务器端。

关闭宠物不删除档案；切换主题清除清理任务，重新启用会恢复。完整迁站备份应包含这两张表。部署需要允许 WordPress 创建表的数据库权限；访问量很低时，WordPress 定时清理会延后至后续站点访问。

## 验证记录

使用隔离的本地测试表验证了投喂/摸摸/阅读限额、重复阅读回滚、评论审核与重新审核、阅读签名、自然日切换、长期离线状态、成长阶段、切换外观保留经验、AI 上下文、断线回退、冷却和全站额度。

并发验证：20 个不同访客请求加 8 个同一访客请求同时执行，准确产生 21 次成长奖励。HTTP 验证覆盖错误 nonce、外站 Origin、伪造阅读凭据和未知操作。浏览器验证覆盖真实按钮、日记问答、后台保存切换和手机布局。

尚未配置真实供应商密钥，因此 AI 成功及失败路径使用模拟响应验证，未执行付费模型请求。测试用表、评论和临时插件不属于交付主题，也不会保留在实际宠物档案中。

## 关节动画（2026-09-06）

每只宠物有六种可预览动作，另有眨眼、思考和说话状态：

| 宠物 | 动作特点 |
| --- | --- |
| 小鸟 | 点头、挥翼、双翼展开、低头啄谷粒、开心拍翼、梳理羽毛 |
| 猫咪 | 点头、抬爪招呼、抻身伸爪、捧食物咀嚼、歪头摆尾、单爪洗脸 |
| 狐狸 | 歪头、挥爪、俯身舒展、吃果子、快速摆尾、回头理尾巴 |
| 兔子 | 点头动耳、招手、立耳伸懒腰、捧胡萝卜、双耳摆动、双爪洗脸 |

小窝「看看我的小动作」可以反复预览，不调用投喂接口，不写成长数据。真实投喂／摸头只有服务端成功后播放吃东西／开心动作；打开面板点头，鼠标进入宠物时打招呼（5 秒冷却），聊天等待与回答分别播放思考和说话动作。

待机每隔 6–13 秒随机挑选眨眼、点头、理毛或舒展，不连续重复同一动作；一次动作约 1.5–2.4 秒。交互动作可以替换待机动作，播放结束恢复原姿态。整张图、占位、脚底阴影不做上下漂移。夜间待机闭眼，不随机做活跃动作；主动互动仍会响应。

页面隐藏、宠物休息、离开视口时停止动作；PJAX 页面切换取消旧动作并重新安排待机，不复制宠物。开启系统「减少动态效果」时不启动关节动画。

验证：浏览器逐项点击四种宠物的六种动作（24 项），检查关节姿态；首页小窝按钮验证两个 SVG 同步、外层不位移、预览不改变成长值。PHP 和 JavaScript 语法检查通过。临时动作检查页面已移除。

## 2026-09-06：真实骨骼宠物

新增 fox3d / shiba3d / husky3d / deer3d 四种外观，使用 Quaternius CC0 的 GLB 蒙皮骨骼模型（约 1.7–2 MB / 只）。原 bird/cat/fox/rabbit 平面外观仍兼容。当前本地预览默认 fox3d；没有更改成长表、统计规则或 AI 服务。

Three.js 0.185.1（MIT）按需加载，单个透明 WebGL 画布在首页位置和小窝之间移动，避免同时建立两个渲染器。约 30 FPS，隐藏页面、离开视口、休息后暂停；减少动态效果时显示静态姿态。WebGL/模型加载失败时显示宠物名称，成长和对话仍可用。

六个预览：站立 Idle、张望 Idle_2、低头 Idle_2_HeadLow（小鹿 Idle_Headlow）、进食 Eating、行走 Walk、跳跃 Jump_ToIdle（小鹿 Jump_toIdle）。约 380ms 混合过渡，动作完成返回站立；投喂成功播放进食。预览不写成长数据。当前没有专门的睡眠或伸懒腰素材，不把现有动作冒充这些行为。

源码 assets/js/src/pet-3d.js；运行时 assets/js/pet-3d-runtime.js；按需入口 assets/js/pet-3d.js。使用 three@0.185.1 和 esbuild@0.28.2：`esbuild assets/js/src/pet-3d.js --bundle --minify --format=esm --outfile=assets/js/pet-3d-runtime.js`。资源来源和许可见 [模型资源说明](../assets/models/README.md)。
